# Troll hostage rescue

1. Open profiles.json. Create each listed stable ID under NPCs and copy its profile fields and creature settings. This is authoring data, not a Restore Backup file. Adjust levels for your party before spawning.
2. Configure Controlled Actions as below. Story text does not grant mechanical permissions.
3. Persistent: spawn each actor with persistent placement, enable AUTO, and paste proposal.txt into Encounters > Describe the encounter. Allow combat if desired. Prepare, review actor assignments and rules, save, enable AI DM monitoring/restart recovery and arm.
4. Live: use the same brief in Live Encounters and select these profiles. Review the generated actors' permissions after placement; profiles do not imply action permissions. Place the trigger, preview and start. Live scenes last until cleanup or server reset.
5. Test as a player. Stay within 3 metres for payment. Closing the exchange pays nothing; only a confirmed receipt counts. Test negotiation, social checks, withdrawal and combat separately.

On Morga, enable actions and payment: starting 100 gold, minimum 75, purpose Elana Voss ransom. Grust must not collect a duplicate ransom. Optionally allow Grust to attack only Elana, under the condition that the player starts actual combat after a hostage warning while the scene is unresolved. Elana must separately allow being targeted. Both need actions and AUTO enabled. Otherwise leave this combat permission off. Player combat permissions are separate. Review social checks, initially DC 15. Test the distinct personalities, a confirmed ransom, alternative negotiation, withdrawal and a combat rescue. Narrative conditions guide the model; target and permission limits are enforced in code.

No automatic rewards, physical bindings or escort are implied. Do not narrate unsupported mechanics as completed. Creature appearance and class do not implement a stock monster stat block or regeneration; level-one trolls are authoring defaults, not balanced enemies.
