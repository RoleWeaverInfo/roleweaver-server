# Role Weaver Server Add-on 1.0.0

The first **1.0 release** of Role Weaver Server Add-on, with separate Demo and
Server Add-on downloads. Application and distribution version: **1.0.0**.
GitHub tag: `v1.0.0`. This is a normal release, not an alpha or prerelease.

## Two downloads

- **RoleWeaver-Demo-1.0.0.tar.gz**: the complete editable Kingdom demo.
  Crown Hall connects to a forest robbery and cave hostage scene. Includes the
  investigation, Royal Guide walkthrough, characters, lore, merchants and examples.
- **RoleWeaver-Server-Addon-1.0.0.tar.gz**: the service and integration tools
  for an existing NWN/NWNX world. Your own module remains in its existing folder.
  An optional example module/content snapshot is included for reference.

Extract on Linux, open **START_HERE.md**, and run **bash setup.sh**.
The reference host is Ubuntu 24.04 x86-64 / Python 3.12. Dedicated-server files,
matching NWNX plugins/headers, Redis and compiler are supplied separately.

## Included since Alpha 0.2.0

- **Familiars:** player opt-in, chat follow-ups, awareness, inventory/errands,
  owner-directed NPC visits, continuity and in-game controls. DM dashboard controls
  include editable starting templates for standard familiar types and custom blueprint
  overrides. Templates are copied once; existing characters retain their memories.
- **Translation:** on-demand examination text, public biographies, supported hover
  labels and prepared standard dialogues. Cached results are reused across players;
  changed source text is translated again. Player names, chat, tells and logs are
  excluded. Translation is optional and configured separately.
- **Multiplayer dialogue:** the optional native adapter delivers private dialogue
  translations per viewer. Public spoken dialogue remains in the server language.
- **Recovery and diagnostics:** rotating verified database snapshots, restore previews,
  independent recovery/health pages, filtered support reports and translation diagnostics.
- **Guided installation:** saved server profiles, dependency checks, path-specific
  Aurora imports, service verification and managed update/rollback.
- **Dashboard login and limits:** a shared server-set password, expiring sessions,
  bounded requests/provider concurrency and batched companion inventory saves.
- **Demo preparation:** current bridge sources compile during setup. The three-area
  world, patrols, shops, investigation, hostage/payment behavior and authored lore
  are retained. New instances start with empty memories and translation caches.

Existing AI NPC actions, merchant stock/haggling, live scenes and persistent AI DM
encounters remain available. Familiar support currently targets wizard/sorcerer
familiars; other companion frameworks require adapters.

## Updating

1. Back up Role Weaver data and your NWN module, overrides, HAKs, character/campaign
   data and launcher separately. Keep old packages and environments until verified.
2. Extract the new addon package. With a saved installation profile, run
   `bash setup.sh update --world my_world`, substituting your world ID.
   The updater preserves config, credentials and data and takes a recovery snapshot.
3. If migrating from older manual tools, follow the migration section in the
   guided setup guide. Do not copy old setup.json over the new guided profile.
4. Review the generated INSTALL.md. Install changed bridge scripts/plugins through
   your world's normal maintenance process, preserving its load/chat hooks.
   A Python update alone does not activate changed native scripts.
5. Verify the game connection and feature permissions. Translation and companions
   remain opt-in. Existing dashboard passwords are kept; a new installation starts
   with **roleweaver**, separate from NWN's DM password.

For the demo, build a fresh instance from this package for a clean test.
Existing `.demo/` folders are private runtime state; keep them with their old
package until backed up. Reusing an instance does not automatically rebuild game
scripts. Follow its customization guide deliberately.

## Limits

- Linux release. The optional NWNX_RWTranslation adapter targets Linux x86-64
  NWN/NWNX **8193.37-17**, with matching Core/source. Source is included; compiled
  native plugins are not. Other ABIs are unverified.
- Without that adapter, standard dialogue translation falls back to original text
  when another player is in the same area. The first uncached request may show the
  original; reopen after translation completes.
- Custom journals, quests, boards, menus and companion systems need specific
  integration. HAK contents are not automatically extracted or catalogued.
- LLM quality, latency, quotas and costs vary. Guardrails are not guarantees; costs
  are estimates. Player consent and game-side action checks remain necessary.
- Keep the password-protected dashboard and Redis private through loopback/SSH.
  Public hosting, TLS and individual DM accounts are not supported here.
- Addon backups do not contain native game saves, modules or credentials.
  Keep an off-machine backup as well.

## Validation and support

The review record distinguishes automated/package/native compilation checks from
player tests. Clean-machine and external-world rehearsals, extended multiplayer
runs and real interruption/recovery exercises remain open. Source tests are not
a guarantee of compatibility with every persistent world.

Third-party asset notes and the remaining inherited-asset provenance review are
recorded in THIRD_PARTY_NOTICES.md.

Report package/runtime versions, NWN/NWNX build, model and reproduction steps.
Use Health & Support and translation diagnostics; review reports before sharing.
Do not publish keys, raw logs, databases or private conversations.
